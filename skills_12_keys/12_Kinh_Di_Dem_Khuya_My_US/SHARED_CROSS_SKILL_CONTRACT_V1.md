# US MIDNIGHT HORROR — SHARED CROSS-SKILL CONTRACT V1.1

> Stable filename retained for installation compatibility with V1; version is **1.1.0**. Authoritative for all five Skills.

## A. Nonnegotiable routing
- Exactly five installed Skills and six external commands: `step1` Title, `step2` Outline, `step3` Writer DRAFT (A/B/C over three invocations), `step4` Independent AUDIT / later FINAL READ-ONLY VERIFY, `step5` Writer ONE-PASS REPAIR (optional, maximum one invocation per video), `step6` SEO. No automatic step advancement. The Writer folder owns BOTH step3 and step5; do not split or renumber it.
- State is persisted in actual files. Never pretend that a saved artifact, checksum, timestamp, score, file count, or external research exists. Reread upstream files at each step.
- Default 8 standalone US first-person stories under ONE collection title, not eight installments of one serial story. Explicit user N=3..12 supported only if title, outline and manifests consistently use N and three stages are allocated deterministically: divide N by 3, distributing remainder to earlier stages. For eight: A=1–3, B=4–6, C=7–8. Zero or missing stages invalid.

## B. Immutable identity, provenance, and format
- Source `TITLE_LOCK.txt` holds the exact single chosen title; preserve quotes, pipes and punctuation. `title_sha12=sha256(locked_title.encode('utf-8'))[:12]`. `outline_sha256=sha256(OUTLINE.md exact saved bytes)`. `video_id=sha256((locked_title+'\n'+outline_sha256).encode('utf-8'))[:16]`. Check `IDENTITY.json` on every stage.
- **No copying a previous video's video_id, SHA, QA gate or release**. If outline or title changes, start a new video identity and reset approval state deliberately. `FULL_SCRIPT.txt` is immutable after draft seal. Script revision is `FULL_SCRIPT_REVISED.txt`, never overwrites original.
- Text is UTF-8 without BOM, LF-only. Pure narrative uses exact standalone headings `STORY 1` through `STORY N`; no Markdown markup in story bodies. All counts are Unicode codepoints in `strip()`ed story bodies (not bytes, not editorial preamble). Word count uses split-on-whitespace; runtime = actual counted English words / explicitly assumed narration WPM, estimate only.
- Maintain `TITLE_LOCK.txt`, `OUTLINE.md`, `IDENTITY.json`, `CANON.json`, `DISTINCTNESS_MATRIX.md`, `STORY_BEATS.md`, `SCRIPT_A.txt`, `SCRIPT_B.txt`, `SCRIPT_C.txt`, `FULL_SCRIPT.txt`, `SCRIPT_MANIFEST.json`, `QA_REPORT.md`, `QA_ISSUES.json` as appropriate. After repair additionally `QA_REPLACEMENTS.json`, `FULL_SCRIPT_REVISED.txt`, `REPAIR_LOCK.json`, `REPAIR_PROOF.json`, `SCRIPT_MANIFEST_REVISED.json`, `FINAL_QA_REPORT.md`, `FINAL_QA_GATE.json`. Step6 produces `SEO.txt`, `THUMBNAIL_PROMPTS.txt`, `TRAILER.txt` and `FINAL_RELEASE_MANIFEST.json`.

## C. Narration and editorial DNA
- Original **fictional** American-English suspense narration, inspired by format and broad subject trends, never transcripts or lifted anecdotes. Do NOT claim fictional original stories are verified `True Horror Stories`, firsthand criminal testimony or actual police records. Avoid exploitation of real people, graphic gore, and crime-commission tutorials.
- Every story must differ on at least narrator, environment, threat mechanism, evidence path, climax and emotional aftertaste. Use >=4 of DNA A–F across 8; avoid back-to-back mirror plots. Ground geography, timing, sightlines, line-of-sight, entrance/exits, vehicle movement, battery/network reception, witness knowledge, proof chain, police arrival, plausible US life and work practices. Suspense comes from choices under incomplete information, not irrational behavior or surprise omniscience.
- Hooks: start with conflict/clue within first 30–80 spoken words. 7-beat causality per story, a meaningful tension shift around middle, differentiated endings. Rotate voice and sentence rhythms; no 8 identical `I still...` epilogues or generic moralizing. Each clue must have an observable origin, a limitation, and a consequence. Contain original distinct emotional stakes.

## D. Length and mechanical policy
- For N=8 target **65,000–78,000** story-body codepoints, HARD range **60,000–83,000**. For other allowed N these limits scale by N/8; per story soft 7,200–10,500 body codepoints, hard floor 5,000 each. Hard length violations BLOCK completion; soft deviations require brief editorial justification but do not automatically block if the story is tight. Avoid padding only to meet quota.
- `python tools/verify_script.py FULL_SCRIPT.txt --count 8` is the script-level mechanical gate. `python tools/verify_project.py PROJECT_DIR` validates identity, exact merged A/B/C, and baseline manifest. After repair use `python tools/verify_project.py PROJECT_DIR --revised` to verify fresh revised counts and exact authorized changes. If tool is unavailable, report `NOT_VERIFIED` and BLOCK automatic release, never forge a PASS.
- Merger MUST be exact `SCRIPT_A` bytes + one LF + `SCRIPT_B` bytes + one LF + `SCRIPT_C` bytes, each stage ending in one LF and subsequent stage starting `STORY #`. Store actual original counts and hashes from persisted bytes. Each stage's story headings must match designated stage allocation.

## E. QA and single repair
- **QA is audit-only**; Writer is the sole repairer. STEP4 must inspect original whole script, story canon and source manifests. Matrix: causal/geographic/time logic 45 points, continuity/source knowledge 20, US spelling/grammar 20, suspense/clarity 10, packaging 5. Qualitative scores are reviewer judgments, not objective certification. Only READY if >=95/100, no unresolved CRITICAL or MAJOR logic issues and no material spelling errors. Missing optional minor canon detail is NOT automatically a major defect; justify severity with reader consequence.
- Produce actionable `QA_ISSUES.json` bound to exact baseline SHA and video_id. Every issue has unique ID, severity, story number, **one exact unique anchor**, rationale, minimum repair criterion and acceptance test. If no repair needed, Step4 may create `FINAL_QA_GATE.json` on baseline SHA with repair_count 0.
- STEP5 executes **exactly one revision operation total per video**, touching only QA-listed spans, focusing (1) physical/narrative logic, (2) continuity/knowledge/time, (3) English spelling, grammar, typos. NO broad prose rewrites, emotional expansion, second rewrite, or silent global polishing. Script utility `tools/apply_one_pass_repair.py` must perform replacement, write proof, AND recalculate `SCRIPT_MANIFEST_REVISED.json`. A persistent `REPAIR_LOCK.json` reserves the one attempt. Never simply edit revised TXT without refreshing manifest.
- After Step5, Step4 performs ONE READ-ONLY FINAL VERIFY against current revised SHA, tests every issue, and writes `FINAL_QA_REPORT.md` + **machine-readable** `FINAL_QA_GATE.json`. **No second repair** even if QA fails; BLOCK_RELEASE and request explicit new video version outside this video identity.
- Required final JSON object: `{"video_id":"...", "current_script_sha256":"...", "repair_count":1, "score":98, "unresolved_critical_or_major":0, "material_language_issues":0, "verified_issue_ids":["H001"], "final_qa_ready":true, "release_gate":"READY"}`. Exact `verified_issue_ids` must include every input repair issue when repair_count=1. Mark whether score is editorial and recounts are mechanical in accompanying report. A claimed gate is not proof of human quality; it is a traceable editorial signoff.

## F. Final release and SEO
- Step6 must first run `python tools/verify_project.py PROJECT_DIR --revised --release` if revised exists, otherwise omit `--revised`. Failure = block SEO. After writing SEO, run `python tools/finalize_release.py PROJECT_DIR --seo`. This verifies current manifest/QA/SEO hash and rebuilds `FINAL_RELEASE_MANIFEST.json` from disk truth; do not hand-write counts.
- Use final current script as only SEO source, preserve exact title lock; no fabricated crime cases, precise audio timestamps or CTR metrics; use voice runtime estimates labeled as assumptions. Metadata and thumbnail prompts must reflect actual eight stories without invented events or unsupported supernatural imagery.

Old V1 production packages can be inspected by V1.1 verifier but will FAIL release until stale manifests and missing new QA gate are independently resolved. **Do not retroactively re-run STEP5 on an already repaired V1 video.**
- Store all project artifacts together in one per-video project folder. Tools may make strong guarantees for that folder; a copied folder or uncontrolled external execution is not a global immutable database. Enforce process permissions and backup policy in the host system.
