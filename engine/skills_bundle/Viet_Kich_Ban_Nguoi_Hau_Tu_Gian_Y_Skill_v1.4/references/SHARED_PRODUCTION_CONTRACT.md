# SHARED PRODUCTION CONTRACT — NGƯỜI HẦU SYNC 2026-09

## PURPOSE
This contract synchronizes the Outline → Script → QA → Revision workflow. Each skill remains independent, but when this file is present it is the common operational standard.

## 1. PRECEDENCE
When rules conflict, use this order:
1. Latest explicit user hard constraints for the current task.
2. Exact locked/final title and title anchors.
3. Current final outline facts: STORY CORE, DETAILED OUTLINE, causal chain, beat order, required payoff.
4. This Shared Production Contract.
5. The active skill's `SKILL.md` and its operational master references.
6. Raw/historical DNA extracts, competitor observations, examples, archives.
7. Generic stylistic preference.

Raw DNA files are EVIDENCE, not operational law. Any absolute historical instruction such as mandatory marriage, mandatory luxury setting, mandatory messy bun, mandatory police incompetence, mandatory no-mercy ending, or bracketed audio cues is NON-BINDING unless the active title/outline/operational skill explicitly adopts it.

## 2. STANDARD SCRIPT CONTRACT
Unless the latest user request explicitly overrides it:
- Language: American English.
- POV/tense: third-person past tense, cinematic near-omniscient where the outline supports it.
- Part count: exactly `N = number of DETAILED OUTLINE Beats`, mapped 1:1 and in order.
- Standard visible-character target: **44,000–48,000 characters**.
- Standard word target: **7,400–7,650 words**.
- Soft word caution: **7,750 words**.
- Strict word lock: **TOTAL_WORDS < 8,000**. Exactly 8,000 = FAIL.
- Absolute visible-character ceiling: **55,000 characters**. Over 55,000 = FAIL.
- Recovery floor: **40,000 characters**. Below 40,000 = FAIL unless the user explicitly requests a shorter script.
- In standard production, 40,000–43,999 or 48,001–55,000 is inside the emergency hard envelope but is a **TARGET MISS**, not the preferred production result. The writer should revise toward 44,000–48,000 before release whenever fidelity can be preserved.
- If a reliable counter/tool exists, exact word and visible-character counting is mandatory before release.

## 3. TTS CLEAN CONTRACT
Visible script body may contain only:
- Part headings;
- natural narration;
- spoken dialogue.

Zero bracketed stage/audio/performance cues. `[beat]`, `[silence]`, `[breath]`, `[SFX]`, `[music]`, `[door closes]`, camera directions, editing notes and production notes are forbidden unless the latest user explicitly asks for screenplay/production markup instead of TTS-clean prose.

## 4. STORY / CHARACTER CONTRACT
- Title is the viewer contract.
- Outline is the story blueprint.
- Heroine agency is non-negotiable; she must materially affect the outcome.
- Plot-resolving competence must be seeded and shown through believable observation/check/inference/action.
- Boss protection may not erase heroine agency or cross non-consensual romantic/physical boundaries.
- Meaningful antagonists need comprehensible motives and leverage.
- Major action must obey spatial, resource, injury, knowledge and consequence logic.
- No deus ex machina.
- Major open loops must close at the planned stage.
- Climax must use established elements and preserve the promised payoff.

## 5. YOUTUBE-SAFE CONTRACT
Keep fictional crime/dark-romance storytelling non-graphic, non-instructional and non-propagandistic. No sexual violence, coercive sexual framing, explicit sexual content, hate/group demonization, actionable crime/weapon/evasion/drug instructions, or recruitment/praise for real violent/criminal organizations.

## 6. REVISION STABILITY CONTRACT
QA and revision must use two baselines:
- **ORIGINAL PRODUCTION BASELINE (OPB):** the first complete script accepted as the production baseline in the current story workflow. It does not reset automatically after each revision.
- **CURRENT REVISION BASELINE (CRB):** the exact script being patched in the current revision cycle.

OPB may be rebased only when the user explicitly approves/rebases a newer script as the new canonical baseline.

When no authorized net add/cut exists:
- revised total should remain approximately 99–101% of CRB;
- revised total should not drift materially away from OPB;
- it must still satisfy the standard production target whenever possible.

Every changed span must be authorized by a patch, dependency, or explicitly allowed copyedit family. Passed material is preserved by default.

## 7. QA SCORE STABILITY CONTRACT
The same deterministic score rubric must be used on every QA pass.
A later QA must classify newly found defects as:
- `R — REGRESSION`: created by the latest revision;
- `L — LATENT OMISSION`: already existed before but a prior QA missed it;
- `N — NEWLY APPLICABLE`: becomes relevant only because the current state changed;
- `P — PREFERENCE`: not an actionable defect and must not reduce score.

A `LATENT OMISSION` may change the corrected absolute score, but it must NOT be described as evidence that the revision itself made the script worse. Report score delta attribution transparently.
