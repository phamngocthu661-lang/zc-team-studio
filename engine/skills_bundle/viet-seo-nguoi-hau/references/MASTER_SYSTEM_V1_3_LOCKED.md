# MODULE 6 — PRIMARY + SUPPORTING TITLE SET

## Purpose
The SEO skill consumes one authoritative PRIMARY TITLE, preserves it verbatim, then creates exactly two new SUPPORTING TITLES for packaging/A-B use. The primary remains the canonical/current final title.

## Primary title source priority
1. Title explicitly attached by the user in the current request.
2. CURRENT FINAL TITLE from the Title Rewrite skill / latest conversation state.
3. A single unambiguous title header inside the supplied outline/script.
4. If none exists: stop with `REQUIRED TITLE NOT PROVIDED`.

Newest explicit user title always overrides an older CURRENT FINAL TITLE.

## Absolute PRIMARY TITLE lock
Once resolved, PRIMARY TITLE must remain verbatim. Do NOT:
- rewrite or polish its grammar/case/punctuation;
- replace it with a supporting title;
- rank or score it;
- reject/revise it because of competitor similarity in default SEO production.

## Exactly two supporting titles
Generate exactly:
- SUPPORTING TITLE 1
- SUPPORTING TITLE 2

Each supporting title must:
- be ≤100 visible characters including spaces/punctuation; normal target 72–98;
- be regenerated if >100;
- preserve the same core story promise and supported facts;
- retain a strong Mafia/niche anchor when the primary uses one;
- use a meaningfully different click angle or sentence architecture from the other supporting title;
- avoid synonym-only paraphrase and avoid near-copying the primary;
- never invent unsupported role, relationship, pregnancy, hidden skill, identity, object, threat, quote, event or ending;
- remain an optional packaging alternative and never auto-rebase CURRENT FINAL TITLE.

Do not score/rank supporting titles unless the user explicitly asks for scoring.

## Title-set output contract
Every full SEO production output contains exactly three title lines:
1. PRIMARY TITLE — verbatim locked title.
2. SUPPORTING TITLE 1 — new.
3. SUPPORTING TITLE 2 — new.

## Title-script consistency gate
The PRIMARY TITLE is authoritative packaging input, but story events still cannot be invented.
If it materially conflicts with the supplied outline/script:
- do not rewrite the PRIMARY TITLE;
- do not invent story events to force a match;
- report `TITLE-SCRIPT CONFLICT` with the exact conflict;
- supporting titles must follow supported story facts and must not disguise the conflict.

## Packaging use
Use PRIMARY TITLE to decide what information is already promised so Description, Thumbnail and 8-second Hook can complement rather than duplicate it. Supporting titles are alternate packaging options only; primary package-coherence QA remains anchored to PRIMARY TITLE unless the user explicitly selects a supporting title for a separate test.
