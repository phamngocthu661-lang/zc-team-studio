# BASELINE PRESERVATION & ONE-SHOT REVISION — NGƯỜI HẦU V1.1

## PURPOSE
Ngăn:
1. càng sửa càng ngắn;
2. sửa lỗi cục bộ nhưng tái sinh cả script;
3. phá outline/DNA/Part map trong revision.

## A. DUAL BASELINE
Record:
- **OPB — ORIGINAL PRODUCTION BASELINE:** first accepted complete production script; never auto-reset;
- **CRB — CURRENT REVISION BASELINE:** exact script entering the current patch cycle;
- source script/version;
- exact chars per Part;
- exact total chars;
- exact total words;
- Part headings/count;
- title;
- outline/DNA if available;
- strong spans;
- standard target 44k–48k chars + 7,400–7,650 words; strict <8k; hard max 55k.

OPB may change only when user explicitly rebases/approves a newer script as canonical production baseline.

## B. PRECEDENCE
1. Latest user hard constraint.
2. Title / outline / Part architecture.
3. Shared production target 44k–48k + 7,400–7,650 + strict <8k + hard max 55k.
4. OPB/CRB preservation.
5. Operational style.
6. Raw/historical DNA evidence.
7. Pure preference.

## C. LENGTH STABILITY
If CRB is in standard target and ledger does not authorize net cut/add:
- unchanged Part: 98–102% CRB Part;
- total: 99–101% CRB total;
- no material cumulative drift away from OPB;
- final target remains 44k–48k chars and 7,400–7,650 words;
- strict <8k and never >55k.

If CRB is inside 40k–55k but outside 44k–48k:
- treat as TARGET MISS and move toward 44k–48k with functional edits inside existing beats.

If CRB <40k:
- add functional content only inside existing beats; target 44k–48k unless user overrides; no padding.

If CRB >55k or >=8,000 words:
- hard failure; cut only authorized redundancy/low-value spans while preserving title payoff, outline beats and strong spans.

## D. FUNCTIONAL REPLACEMENT
Allowed additions:
- causality bridge;
- heroine competence process;
- consequence/reaction;
- relationship-state transition;
- antagonist motive/leverage;
- tension/pressure;
- sensory/spatial grounding;
- injury recovery;
- setup/payoff clarification.

Forbidden:
- filler;
- repeated theme;
- new subplot/mastermind;
- new Part;
- decorative luxury detail only to hit count.

## E. STRONG-SPAN FREEZE
PASS text should not be paraphrased, shortened, moved or re-dialogued unless dependency requires micro-change.

## F. SURGICAL PATCH DEFAULT
ORIGINAL SPAN → PATCHED SPAN.
Never ORIGINAL SCRIPT → GENERATE NEW SCRIPT FROM MEMORY.

## G. ENTIRE-PART SCAFFOLD RECONSTRUCTION
When authorized:
1. copy MUST PRESERVE spans into scaffold;
2. preserve mapped Outline Beat function/order;
3. rewrite MUST CHANGE zones;
4. bridge minimally;
5. match target length;
6. preserve continuity and relationship state.

## H. NO COMPRESSION SPILLOVER
`tighten`, `reduce AI prose`, `remove repetition`, `compress` are LOCAL unless ledger enumerates global occurrences.

## I. AUTHORIZED DIFF
Every changed span maps to:
- Pxx/Oxx;
- DEP(Pxx);
- authorized spelling/format family.

Unmapped change → revert.

## J. PART COUNT REGRESSION
After rewrite:
- same number of Parts as baseline/outline;
- same Beat→Part mapping;
- no hidden merge/split.

## K. LENGTH REGRESSION
For each Part and total:
- OPB chars;
- CRB chars;
- Revised chars;
- exact total words;
- Delta / Delta %;
- authorized reason;
- 44k–48k target check;
- 7,400–7,650 target check;
- <8k and <=55k hard checks.

## L. ONE-SHOT FINALIZER
Patch completeness → Authorized Diff → Part Count → Length → Outline/DNA → Canon/Knowledge/Object/Injury/Relationship → Action/Professional Logic → Hook/Retention → Human Prose/Language → YouTube → Blind Read #1 → Blind Read #2 → Stability.
